# Implementation Plan: Round Briefing

**Branch**: `008-round-briefing` (feature identifier returned by Spec Kit; current Git branch: `thyphuongdang`) | **Date**: 2026-10-18 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/008-round-briefing/spec.md`, including both accepted clarifications.

## Summary

Insert an untimed two-step briefing before a valid level starts: crew capabilities, then every scheduled problem. Start Round alone creates the timed round. Reuse the same briefing data for a read-only reference available during play while time continues. Preserve scheduled releases, crew rules, results, normal pauses, free-look maps, and decorate mode.

Build a pure application projection from existing level/map/domain rules, extend the screen machine for preparation, coordinate lifecycle in LevelRun and GameSession, and render a dedicated DOM adapter. No new dependencies, services, persistence, or gameplay balance changes.

## Technical Context

**Language/Version**: Plain JavaScript ES2020, HTML5, CSS; existing MCW namespace and script-tag loading.

**Primary Dependencies**: Existing Canvas renderer; MCW.ScreenMachine, GameSession, LevelRun, Round; levelCrews, jobs, matchLevel, repairSeconds, incidentKinds, jobArt, objectTypes, and map.getObject. No new packages.

**Storage**: Ephemeral in-memory briefing projection and navigation state. Existing level/map files remain authoritative. No saves or migrations.

**Testing**: Existing browser-only harness in tests/index.html; focused projection, state-transition, and LevelRun tests plus manual UI playtest in quickstart.md.

**Target Platform**: Current desktop Chromium and Firefox, offline file opening or any static host; mouse and keyboard.

**Project Type**: Browser game with four inward-dependent layers and one composition root.

**Performance Goals**: Retain 60 FPS during normal play and first interactive screen within 5 seconds. Construct briefing data once per preparation entry; build reference DOM on open, not every frame.

**Constraints**: No backend, install, transpiler, build tool, or unpinned external dependency. Domain/application contain no DOM, asset paths, image loading, or browser timers. First launch remains playable.

**Scale/Scope**: One current trial, four crews, 18 scheduled occurrences, three phases totaling 240 seconds, target 10 repairs. Existing level validation supports up to six crews. Workload rendering must not truncate arbitrary valid schedules.
